# RAM36: снимки маяка и ключей без зависания отчётов

**Аппаратный результат:** владелец увидел C80-RAM36, но не подключал клиент.
Live diag вернул три снимка, после stop — четыре. При установленных GTK/BMC
счётчик маяков показал357 за36,54секунды после post-GTK capture. Остановка
чистая, ошибки команд отсутствуют. [Подробности](VALIDATION.md).
WPA2-подключение ещё не проверено; причина отличия от RAM35 не установлена.

RAM35 сохранила AP после настройки сети, но владелец не обнаружил SSID.
AP работала 468994454 us, радио приняло 14526 кадров, TSF вырос на469062196 us.
Все команды приняты, остановка чистая. Старый beacon_end показал MIB_SDR0=0,
но снимался уже после удаления GTK/BMC. Поэтому этот ноль сам по себе не
доказывает отсутствие передачи до очистки.

Предложенное чтение radio/beacon/state/watch/scheduler во время AP зависло:
старые show ждут mutex, удерживаемый всем c80_run. Второй SSH и c80-wifi stop
освободили отчёты без отключения питания. Это была ошибка нашей диагностики.

RAM36 исправляет диагностику, **не заявляет исправление видимости SSID**.
Сохраняются четыре наблюдения: до подготовки GTK, после создания BMC, после
установки GTK и перед любой очисткой ключей/STA. MMIO читает только MCU-поток,
тем же проверенным набором MAC-регистров, с HIF guard. Копия публикуется под
короткой spinlock; новый beacon_diag и c80-wifi diag читают только CPU-память.
MIB может очищаться при захвате: выводятся сырые значения интервалов, не итог
передач. При guard fault дополнительные MAC-чтения пропускаются.

13 прежних отчётов используют trylock и сразу возвращают EBUSY при работающем
тесте. После Finished они доступны как раньше. Заголовок beacon теперь
показывает фактические длины из nl80211 вместо фиксированных RAM16-литералов.
Форматы команд MCU/радио/ключей и конструктор маяка при одинаковых входах,
DMA pool и его offsets прежние. Имя сети изменено с C80-RAM35 на C80-RAM36,
поэтому байты SSID в шаблоне маяка отличаются. Поле исходного PROVENANCE
radio_key_and_beacon_command_bytes_unchanged относится к одинаковым входным
шаблонам, а не к буквальной идентичности шаблона после переименования SSID.

**Повторный запуск после reboot:** SSID снова не найден. Все четыре raw
счётчика0, включая pre-cleanup через241,50секунды после GTK. AP активна,
ключ установлен, ошибки команд отсутствуют, stop чистый. Следующий опыт —
[RAM37 на канале1](../openwrt-ram37-channel1/) по запросу владельца.

## Следующая проверка на канале1

Текущая RAM36 уже остановлена. Подготовлена отдельная RAM37 на канале1:
порядок замены TFTP-файлов и команды приведены в её README. Нагрузочный
тест пока не нужен; проверяются видимость, один WPA2/DHCP клиент и малый ping.

Ниже сохранена инструкция первоначальной установки RAM36.

## Первоначальная установка

Владелец уже остановил RAM35: Finished/result0, DMA idle, MCU stopped.
В корень прежнего TFTP192.168.0.3 скопируйте:

- c80-openwrt-ram36-beacon-diag-zImage
- c80-openwrt-ram36-beacon-diag.dtb
- c80-openwrt-ram36-handoff.bin
- c80-auth.cpio

**Последним замените c80-start.txt.** Сохраните предыдущие файлы/manifest.
Выполните reboot по LAN1 SSH. U-Boot автоматически скачает файлы; новых записей
NOR/U-Boot нет. SSH root@192.168.0.1, пароль openwrt, серверные ключи прежние.
uname -r должен показать 6.12.113-c80-openwrt-ram36-beacon-diag.

По одной команде:

```sh
c80-wifi start
c80-wifi diag
```

Сохраните первый diag: ожидаются active1/finished0 и saved=7, три снимка ключа.
Обновите поиск Wi-Fi на телефоне/ПК и проверьте C80-RAM36 в течение20–30секунд.
WPA2-PSK/CCMP пароль openwrt123. Если сеть видна, можно подключить один клиент
с автоматическим DHCP192.168.2.2; AP192.168.2.1. Пока не нужен нагрузочный тест.

Затем c80-wifi stop, c80-wifi status до Finished, c80-wifi diag и c80-wifi report.
Пришлите оба diag и полный report, а также результат поиска SSID. Второй diag
должен иметь saved=f, включая before_security_cleanup с состоянием до удаления
GTK/BMC. При повторном подключении/передаче возможны дополнительные данные,
но физический WPA2-путь пока не доказан. После stop повторный start требует reboot.

## Программная проверка

3624 native ASan/UBSan cases заново: прежние3576 и48 новых с реальными core/key
функциями и синтетическим MMIO. Новые cases проверяют порядок четырёх снимков,
состояние ключей/команд, неизменные OEM-пакеты, guard/refusal и сохранение копии
после удаления ключей.13 OEM ARM builder cases выполнены заново.

В QEMU проверяются32 вызова настоящих ARM show/publish функций с удерживаемой
run-блокировкой и без неё. Этот test-only код отсутствует в физическом ядре.
Он запускается до /init, временно подставляет CPU-only контекст и восстанавливает
прежний неактивный C80 DT-контекст. Никакие MMIO/firmware/DMA им не исполняются.
Общий WPA2 harness выполняет37 проверок настоящих hostapd/cfg80211/OpenWrt,
включая независимый PMK/PTK/MIC/AES unwrap, отказ неправильного MIC, два
подключения,13 Linux DHCP/ARP/ICMP/UDP/TCP checks и pinned SSH password login.
Ещё13 startup-removal checks проверяют прежнюю lifecycle-защиту.

QEMU использует синтетическую установку ключей и не эмулирует физические
MCU/CCMP/DMA/RF. Проверены source/rootfs restoration, signed-package/ELF closure,
декомпрессор, handoff, restart и размещение ядра ниже auth-initrd. Полный
31-файловый Linux patch и ram35-to-ram36.patch входят в архив. Производственные
изменения CPU-only; полный DMA pool668112B не расширялся.

Ограничения прежние: один клиент, канал6/CCK/MTU1400; группа превращается в
PTK-unicast, GTK rekey отключён. Нет PMF/WPA3/5GHz/HT/VHT/multiclient,
полного UCI wifi up или AP stop/start в одной загрузке. NOR остаётся MTD_ROM.

Сборка: source ../../activate.sh; bash build-kernel.sh; bash build-qemu.sh.
Нужны исходный Linux6.12.113 и инструменты/пакеты из соседних стадий; отсутствие
кэша восстанавливается restore-source.py/restore-rootfs.py. Проверки запускаются
в рабочей копии, до выпуска ZIP; выданные manifest-файлы и архив неизменяемы.
Для QEMU/Unicorn нужны пути инструментов из ../ram-probe/tools и ../openwrt-ram1.

Архив персональный: прежние SSH-ключи находятся в c80-auth.cpio, OEM firmware
сохранены для локальной сборки. В публичный Git экспортируются только наши
исходники/патчи/шаблоны; ZIP/CPIO/ключи/OEM binaries/калибровка/сырые логи туда
не попадают. Новые аппаратные результаты сохраняются отдельно от frozen members.

Публичные шаблоны rootfs находятся в overrides/. Восстановление персонального
rootfs/SSH overlay и OEM firmware требует локальных входных файлов; они не
входят в этот Git-снимок. Общие prerequisites: ../../docs/BUILD.md.
