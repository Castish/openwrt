# RAM35: сохранить AP при настройке сети

В RAM34 после успешного START_AP помощник вызывал ifup wifi_ram. Эта команда
включает network reload и down/up. В аппаратном логе через секунду после
AP-ENABLED hostapd получил пустую конфигурацию phy0 и удалил AP. SSID не
обнаружился, клиентов/EAPOL не было; помощник уже сообщил об успехе.

RAM35 поднимает netdev и присоединяет его к netifd до запуска AP; вместо ifup
вызывает прямой ubus up без перезагрузки сетевой конфигурации. После DHCP
проверяет active/finished. Общая библиотека запрещает подготовку работающей AP
и отвергает ложный успех после её остановки. Только пользовательский слой:
32 C/header/ASM inputs и полный Linux-патч идентичны RAM34. Изменены helper,
тестовый SSID и добавлен c80_wifi_lifecycle.sh; пакеты/OEM blobs не менялись.

**На плате RAM35 сохранила AP, но SSID не обнаружен.**
active1/finished0/starts1/stops0, GTK/BMC установлены, MCU-команды подтверждены.
После469 секунд чистая остановка:32/32/32 commands,0fault, DMA idle/MCU stopped.
TSF шёл, радио принимало соседние маяки. Ноль в beacon_end прочитан уже после
удаления GTK/BMC и не доказывает отсутствие ранней передачи. Попытка прочитать
legacy radio/state live ждала run-mutex; второй SSH/stop освободил отчёт.
Новая [RAM36](../openwrt-ram36-beacon-diag/) сохраняет снимки до/после ключей
и до очистки, а чтение legacy-отчётов делает неблокирующим.
Физические WPA2/CCMP и видимость SSID пока не подтверждены.

Ниже — исходная программная проверка выпуска RAM35. Свежие36 QEMU проверок выполняют настоящий
hostapd WPA2, DHCP/IP/TCP, повторное подключение и ту же lifecycle-библиотеку.
Сетевой интерфейс уже UP перед AP; после DHCP AP остаётся активной. Ещё13
проверок инъецируют наблюдаемую пустую конфигурацию: реальный STOP_AP приводит
к отказу помощника сообщить об успехе. QEMU не воспроизвёл аппаратный тайминг
одним ifup; отрицательный диагностический результат не скрыт. Это проверка
наблюдаемого удаления и защиты от него, не эмуляция RF/MCU/CCMP/DMA.

3576 native и13 OEM ARM builder сценариев унаследованы по точному сравнению
неизменившихся исходников; заново не запускались. Новые сборки прошли также
проверки handoff/restart/layout, восстановления86728 source entries и601
rootfs entries. [Подробности проверки](VALIDATION.md).

Тестовая сеть C80-RAM35, WPA2-PSK/CCMP, пароль openwrt123. Один клиент,
канал6/CCK/MTU1400; DHCP192.168.2.2/24, AP192.168.2.1. Загрузка через прежний
TFTP/модифицированный U-Boot: четыре личных файла, manifest последним, reboot
через LAN1 SSH, затем c80-wifi start/status. Новый NOR/UBoot write не нужен;
root-пароль openwrt и серверные ключи прежние. AP должна остаться active1,
finished0. При проблеме сохранить status и logread -e hostapd, затем stop,
дождаться Finished и report. AP stop/start в том же boot требует reboot.

Полный31-файловый Linux-патч сохранён; ram34-to-ram35-rootfs.patch содержит
только rootfs-разницу. Общие build prerequisites — ../../docs/BUILD.md.
Шаблоны в overrides/, c80_wifi_lifecycle.sh копируется в usr/libexec/.
QEMU kernel не предназначен для роутера. Как в RAM34, не поддерживаются
GTK rekey, PMF/WPA3,5ГГц/HT/VHT, несколько клиентов и полная UCI wifi up.

Персональные ZIP/CPIO/SSH-ключи, OEM firmware, калибровка и сырые логи в Git
не публикуются. Собственные исходники перечислены в SOURCE-MANIFEST.json
и побайтно совпадают с неизменяемым рабочим архивом.
