# Длительная проверка WPA2 на RAM40

Оставьте компьютер подключённым к C80-RAM40 с автоматическим IP. Распакуйте
архив в отдельную папку и выполните в Windows PowerShell из этой папки:

```powershell
.\c80-wifi-load.ps1
```

Тест занимает примерно четыре минуты: 5000 маленьких ping, 256 ping с
нагрузкой 1372 байта и DF, затем проверка сохранения связи и TCP/22.
Исходящий адрес должен быть 192.168.2.2, цель — 192.168.2.1. Если маршрут
сменится на другой интерфейс или подряд не пройдут десять запросов,
сценарий остановится и сохранит частичный результат. Единичные потери
учитываются; завершение теста само по себе не означает отсутствие потерь.

Результат c80-wifi-load-*.json появится рядом со сценарием. Пришлите его
содержимое или итоговый вывод PowerShell. Сценарий не меняет сетевые
настройки, не перезагружает роутер и не требует замены файлов TFTP.

После завершения, включая досрочную остановку, через SSH по LAN1 выполните
команды отдельно:

```sh
c80-wifi stop
c80-wifi status
c80-wifi report
```

Последнюю команду выполняйте после Finished в status. Сохраните полный
отчёт до перезагрузки. Повторный start AP в той же загрузке не поддерживается.

Это проверка устойчивости одного WPA2-клиента, а не максимальной скорости.
Исходники verifier/package включены для воспроизводимости; запускать их
на компьютере для аппаратного теста не требуется. Проверки управления
сценарием прошли в PowerShell 7.5.4 с синтетическими маршрутами/ответами/
часами. Windows PowerShell 5.1 и физический обмен этим новым сценарием ещё
не проверены. Реальный .NET loopback в облаке не выполнен: в среде нет
системной утилиты ping, которая требуется реализации .NET на Linux.
