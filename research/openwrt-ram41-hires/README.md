# RAM41: точные таймеры, прежние радио и WPA2

В ядре включён CONFIG_HIGH_RES_TIMERS. HZ остаётся 100; вместе с точными
таймерами автоматически включаются TICK_ONESHOT и SCHED_HRTICK. Исходники
драйверов, интервал опроса DMA, скорость передачи AP 1 Мбит/с, канал 1,
MTU 1400 и политика WPA2-PSK/CCMP сохранены от RAM40. Имя сети — C80-RAM41.

В RAM40 длительный аппаратный прогон прошёл без потерь: 5000 маленьких,
256 крупных DF и 89 последующих ping; TCP/22 доступен. Средние RTT составили
9,82 / 23,25 / 9,99 мс, 42 оборота кольца и один оборот токенов без ошибок.
Это исходный замер для сравнения. Аппаратный тест RAM41 ещё не выполнен.

## Обновление через прежнюю автоматическую TFTP-загрузку

В корень TFTP на компьютере 192.168.0.3 скопируйте:

- c80-openwrt-ram41-hires-zImage
- c80-openwrt-ram41-hires.dtb
- c80-openwrt-ram41-handoff.bin
- c80-auth.cpio

Последним замените c80-start.txt из этого архива. Прежние файлы RAM40 можно
оставить рядом. В SSH через LAN1 выполните обычный reboot. UART, запись
U-Boot/NOR и отключение питания для этого обновления не нужны.

После автоматической загрузки снова подключитесь по LAN1:

```sh
uname -r
c80-wifi start
```

Ожидается 6.12.113-c80-openwrt-ram41-hires. На компьютере подключитесь к
C80-RAM41 с паролем openwrt123, IPv4 автоматически. В PowerShell запустите
прежний сценарий, также приложенный сюда без изменений:

```powershell
.\c80-wifi-load.ps1
```

После завершения сохраните вывод Windows и через LAN1 выполните команды
отдельно:

```sh
c80-wifi stop
c80-wifi status
c80-wifi report
```

Последнюю команду выполняйте после Finished в status. Пришлите весь отчёт
и результаты Windows. Отчёт теперь содержит строку C80 timers v1: разрешение
таймеров Linux и 64 измерения сна на 1 мс. Она поможет проверить, заработал
ли новый режим на плате, без дополнительных ручных команд. До сохранения
отчёта оставайтесь в OpenWrt. Повторный start AP в той же загрузке не поддерживается.

Идентичность SSH и пароль root openwrt сохранены. c80-auth.cpio содержит
прежние индивидуальные ключи этого роутера; персональный ZIP не предназначен
для публикации или других устройств.

## Что проверено программно

Физическое и отдельное QEMU-ядро собраны с точными таймерами. В QEMU один
и тот же ARM-диагностический файл запущен на неизменном RAM40 и на RAM41:
64 реальных nanosleep в каждом, clock_getres 10 000 000 нс против 1 нс.
Среднее ожидание 1 мс составило около 9,88 мс против 1,60 мс. Это измерение
системных вызовов в QEMU, а не задержки Wi-Fi на устройстве. Значение 1 нс —
разрешение, объявленное Linux; оно не означает физическую точность в 1 нс.

Повторно пройдены 48 QEMU-проверок hostapd/WPA2/cfg80211, включая независимые
PMK/PTK/MIC/AES unwrap, неверный MIC, два программных подключения, 13 проверок
Linux DHCP/IP/TCP и вход по SSH с проверкой сохранённого ключа. Ещё 13 проверок
подтверждают штатную остановку AP. QEMU не моделирует MCU, DMA, CCMP и радио
реального MT7626. Память и границы размещения образов проверяются отдельно.

Все исходники драйверов и полный 32-файловый патч Linux совпадают с RAM40.
3871 native-проверка и 23 OEM ARM-проверки наследуются по совпадающим
исходникам; заново они не запускались. Свежие проверки исполняют фактический
ARM-код декомпрессора, handoff и restart. Полное восстановление исходников
из Linux tar/патча, rootfs и его библиотечные зависимости также проверены.

В rootfs изменены только метки версии/SSID в c80-wifi и конфигурации hostapd,
в report добавлен диагностический вызов, а c80-timer-check собран из нашего
freestanding ARM-кода без новой библиотеки. Пакеты и firmware прежние.
PROVENANCE.json и package-manifest.json связывают точные исходники и артефакты.

Публичные шаблоны rootfs находятся в overrides/. Бинарный c80-timer-check
собирается из c80_timer_check.c через build-timer-check.py; бинарник, персональный
SSH overlay, OEM firmware и Linux tar в Git не входят. Зависимости: ../../docs/BUILD.md.
