# RAM32: cfg80211/nl80211 и штатный hostapd

Открытая AP C80-RAM32 управляется немодифицированным hostapd OpenWrt через
nl80211. Свой драйвер регистрирует wiphy/AP, передаёт шаблон beacon в MCU,
показывает клиента через iw и сообщает события ассоциации. Передачу данных
обслуживает аппаратно проверенный транспорт RAM31 с прежним DMA scheduler.

**Аппаратный тест RAM32 пройден** на Archer C80 v1 RU: hostapd включил AP,
iw показал авторизованного клиента,20/20 обычных и3/3 DF ping прошли,
TCP/22 доступен; остановка завершилась с result/cleanup/critical=0,
DMA idle и MCU stopped. Обезличенный отчёт: [VALIDATION.md](VALIDATION.md).
Он дополняет прежние программные проверки QEMU с синтетическим peer без
эмуляции RF/MCU/DMA. Хеши исходников: SOURCE-MANIFEST.json.

Ограничения: открытая сеть/канал6/CCK/MTU1400, один клиент и одна сессия
до stop/fault/reboot. WPA2, повторная ассоциация, несколько клиентов и полная
интеграция UCI wifi up ещё не реализованы. MCU подготавливает c80-wifi start;
затем служба procd/hostapd запускает AP через стандартный ubus config_set.

Полный патч Linux6.12.113: linux-mt7626-bringup.patch; разница с RAM31:
ram31-to-ram32.patch. Собственные rootfs-скрипты и конфигурационные шаблоны
лежат в overrides/; их пути соответствуют будущему rootfs/.
Общие зависимости и структура сборки: ../../docs/BUILD.md.

Личный загрузочный архив, c80-auth.cpio, rootfs CPIO с OEM blobs, бинарные
оракулы и сырые логи в публичный Git не входят. Идентичность SSH каждый
владелец генерирует локально по шаблону ../ssh-identity-v1/.
