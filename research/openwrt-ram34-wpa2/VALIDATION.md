# Проверка RAM34

Аппаратный тест RAM34 выявил остановку AP до подключения клиента.
После AP-ENABLED через секунду пришла пустая конфигурация phy0 и AP-DISABLED.
SSID не обнаружен; status active0/finished1/result0, starts1/stops1,0 EAPOL,
одна GTK-команда принята,32 MCU-команды подтверждены без command fault.
post-AP ifup wifi_ram вызывает network reload и down/up, что удаляет вручную
созданную AP. Исправление — [RAM35](../openwrt-ram35-netup/); оно ещё ожидает
аппаратной проверки. Рукопожатие WPA2 и CCMP на плате не проверены.

Ниже сохранены пределы исходной программной проверки. Предыдущая RAM33 подтвердила
на плате8 соединений при одном AP start,7 переподключений и чистый stop.
Это не является подтверждением CCMP RAM34.

- 3576 native ASan/UBSan сценариев, включая18 IRQ и101 новый security case.
- 13 выполнений OEM ARM builders с синтетическими OS/ключами/контекстом:
 GTK/PTK install/remove, BMC STA, port authorization, TXD protect, BSS cipher4.
- 31 проверка реальных cfg80211/nl80211/штатного hostapd в QEMU: независимый
 PMK/PTK/MIC/AES unwrap, отказ неверного M2 MIC, успешный M4, две авторизации
 при одном AP start, удаление PTK/закрытие порта, штатный stop.
- 13 проверок реального Linux/DHCP/ARP/ICMP/UDP/TCP после авторизации.
-Один вход SSH с проверкой закреплённой идентичности и прежним root-паролем.
-Полный патч31 файла применяется без fuzz/offset;86728 source entries
 восстановлены побайтно;600 rootfs entries восстановлены без host root/mknod.

QEMU подтверждает userspace/контракты Linux при синтетическом принятии ключей.
Он не подтверждает CCMP engine, реальный MCU, RF, производительность или
безошибочное завершение DMA. Native-модель также не заменяет аппаратный тест.
Не проверены GTK rekey, WPA3/PMF, несколько клиентов и5ГГц.

На плате требуется подключение с WPA2, DHCP, ping с правильным Wi-Fi-маршрутом,
повторное подключение до stop и итоговый report. Сырые логи хранятся приватно;
после теста сюда добавляется обезличенный результат без изменения исходников.
