# RAM33: повторное подключение клиента при работающей AP

В RAM32 AUTH/ASSOC обслуживались однократно. RAM33 добавляет цикл клиента
в потоке MCU: остановить новые данные, дождаться обеих границ завершения TX,
удалить STA с подтверждением MCU, затем обработать AUTH/ASSOC или REASSOC.
Beacon и штатный hostapd продолжают работать. Ответы проходят через прежнее
кольцо с контролем DDONE/TX-free; команды MCU используют два дополнительных
буфера и128 дескрипторов без сброса живых индексов. Старые DMA-смещения сохранены.

Добавлен наблюдательный /sys/kernel/c80_wifi/session: счётчики подключений,
создания/удаления STA, завершений TX и оборотов команд. Повторный AUTH во время
ответа не удаляет STA повторно. Linux сообщает NEW_STA/DEL_STA и ведёт статистику
текущего клиента. Завершение службы hostapd имеет одного владельца cleanup.

**Аппаратная проверка повторного подключения RAM33 пройдена.** Владелец
подтвердил 8 подключений одного клиента (7 повторных) и 8 отключений при
одном запуске AP; 10/10 показанных ping без потерь и чистую остановку.
[Подробности и границы проверки](VALIDATION.md).

Перед выдачей сборки пройдены2591 базовый+18 IRQ+652
cfg control+214 новых ASan/UBSan-сценариев. В native-модели — до5000 сессий,
обе очередности завершения, отключение при занятом TX, ошибки событий/кадров,
обороты колец и токенов. В двух загрузках32МиБ QEMU настоящий hostapd/cfg80211
прошёл44+47 команд, включая три подключения synthetic peer при одном AP start.
Четыре входа SSH проверены с прежней закреплённой серверной идентичностью.
Дополнительно выполнены8 трасс настоящего OEM ARM-кода ответа REASSOC.
QEMU не эмулирует RF/MCU/DMA; новый native session-mode не исполняет весь
c80_run от загрузки до teardown. Результат физической проверки приведён выше.

Проверенный сценарий: один раз c80-wifi start, подключить клиент к C80-RAM33,
**до stop** выключить/включить Wi-Fi клиента и подключиться снова. session
показывает рост connections/creates/deletes без перезапуска AP. После stop
нужно дождаться Finished, затем собрать report. Сырые логи приватны.

Ограничения: один открытый клиент, канал6/CCK/MTU1400. Переподключение внутри
запущенной AP реализовано; AP stop/start в том же boot пока требует reboot.
WPA2, несколько одновременных клиентов и полная UCI wifi up интеграция не готовы.
Операторский kick/deauth через nl80211 пока не поддерживается.

Полный патч Linux6.12.113 — linux-mt7626-bringup.patch (26 файлов), разница
с RAM32 — ram32-to-ram33.patch. Наши rootfs-шаблоны находятся в overrides/;
копируйте их по тем же относительным путям в локально собранный rootfs.
Общие зависимости: ../../docs/BUILD.md. Версии45 подписанных OpenWrt пакетов
сохранены в packages.lock. OEM firmware и per-device SSH overlay предоставляются
локально, по шаблону ../ssh-identity-v1/. Готовый личный ZIP, ключи, OEM blobs,
дампы калибровки и сырые аппаратные отчёты в Git не входят.
